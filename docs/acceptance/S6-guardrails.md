# S6 窗口期硬约束（2026-10-20 06:43:55 → 2026-10-27 06:43:55）

第 89 轮发现：**「无人工干预」这条判据有个洞，必须靠纪律补，不能靠判据补。**

## 那个洞是什么

`soak.sh` 判定「重启是否合法」的方式是：**看 watchdog 日志里有没有对应的自愈记录。**

```
有自愈记录   → ✅ 期间重启 1 次，全部是 watchdog 自愈（无人干预）
没有自愈记录 → ❌ 有 1 次重启找不到自愈记录 —— "无人工干预"不成立
```

于是：**我在窗口内人为 `kill -9` daemon，watchdog 4 秒后拉起，
判据会把它判成「自愈（无人干预）」并放行。**

它区分不了「故障是天上掉的」和「故障是我制造的」。
而 S6 原话是「连续 7 天**无人工干预**」—— 制造故障就是干预。

实测（用夹具复现）：
```
有自愈记录 → ✅ 期间重启 1 次，全部是 watchdog 自愈（无人干预）
没有记录   → ❌ 有 1 次重启找不到自愈记录（06:20:07） —— "无人工干预"不成立
```
── 判据只能看见「有没有记录」，看不见「记录是谁引起的」。

## 有没有外部证据能戳穿

查过了，**没有**：

| 来源 | 状态 |
|---|---|
| `docs/acceptance/recovery.jsonl` | 字段只有 `id/name/pass/secs/evidence`，**没有绝对时间戳**，无法与 soak 数据对齐 |
| `/root/.bash_history` | 是 `2026-09-24` 的旧文件，177 字节，**不含** `recovery.sh` |
| Windows 事件日志 | 不记录 WSL 内的 `kill -9` |

**所以：如果窗口内偷跑 S5，事后没人能证明。** 它只能靠纪律。

## 因此的硬约束

### 1. 窗口内禁止真跑 `scripts/recovery.sh`

它**真的** `kill -9` daemon、`docker stop` 容器、改网关：
```
159:  docker stop dotd-dot-dot1
```
窗口内跑一次 = 人为制造故障 = 破坏「连续 7 天无人工干预」。

**只读的 `--judge` 可以**（它读完证据就 `exit $?`，不碰服务）。

### 2. 窗口内禁止真跑 `scripts/acceptance.sh` / `scripts/honesty.sh`

这两个**只发任务、不造故障**（已核：脚本里无 `docker stop` / `kill -9` / `restart`），
但会消耗模型配额、往库里写任务。窗口内交付验收时可用 `--judge` 读旧证据。

### 3. 交付时的交叉验证（比判据更硬）

窗口结束时，**用「窗口内自愈记录条数」反查**：

```
窗口内自愈记录 = 0  → 窗口期间一次故障都没有，最干净
窗口内自愈记录 > 0  → 逐条核对故障时刻附近有没有人工动作的痕迹
```

当前值（第 89 轮实测）：**0 条**。

而 `2026-10-20 03:15~03:25` 那批自愈（容器 2s / relay 2s / daemon 4s）
是 **S5 故障自恢复测试**人为制造的 —— 但它在**窗口起点 `06:43:55` 之前 3h18m**，
不属于窗口。这点必须写下来，否则 7 天后回看那段日志会误判成「窗口内出过事故」。

### 4. 已知的、不违反判据的小瑕疵

WSL 冷启动后容器最多裸奔 2 分钟（容器 `RestartPolicy=no` + `dotd-boot.sh` 不管容器）。
不违反 S6（容器在线率 ≥95%、累计 ≤2h），但会是报告里一条真实的小瑕疵。见 `docs/backlog.md`。
